# 패턴 통계 관문 (Phase 20b)

> 이 프로젝트에서 **가장 컸던 통계적 약점**을 정면으로 다룬 문서입니다.

---

## 1. 문제

이전 버전의 `PROJECT_STATUS.md` 에는 이렇게 적혀 있었습니다.

> **Pattern Miner 다중검정 미보정** — 153개 테스트 시 5%는 우연히 유의.
> **가장 큰 통계적 약점**

이게 무슨 뜻인지 구체적으로 보겠습니다.

- 조건 조합 후보를 **153개** 만들어 각각 "승률이 50%와 다른가"를 검정합니다
- 유의수준 5% 로 검정하면, **우위가 전혀 없는 세계에서도** 약 8개가
  우연히 "유의"하게 나옵니다
- 그때 `STRONG 8개 발견` 이라고 보고하면, 그 8개는 **아무 의미가 없습니다**

동전 153개를 던져서 앞면이 많이 나온 8개를 골라놓고
"이 동전들은 앞면이 잘 나옵니다"라고 말하는 것과 같습니다.

---

## 2. 넣은 관문 4개

패턴이 `STRONG` 이 되려면 **전부** 통과해야 합니다.

```
후보 153개
   │
   ├─ (1) 3구간 분할 (TRAIN / VALIDATION / OOS) ......... 기존
   │
   ├─ (2) Walk-forward 일관성 ≥ 60% .................... ★ 신규
   │
   ├─ (3) 겹치는 표본 보정 (n_eff = n / horizon) ........ ★ 신규
   │
   └─ (4) 다중검정 보정 (Benjamini-Hochberg FDR) ........ ★ 신규
              │
           STRONG
```

---

## 3. (2) Walk-forward — "한 번의 운"을 걸러냅니다

3구간 분할은 **한 번만** 자릅니다. OOS 구간이 마침 상승장이면
매수 패턴은 전부 통과합니다. 그건 실력이 아니라 자르기 운입니다.

Walk-forward 는 창을 앞으로 밀며 여러 번 반복합니다.

```
[학습        ][검증]
     [학습        ][검증]
          [학습        ][검증]
               [학습        ][검증]
                    [학습        ][검증]
```

각 회차에서 "학습 구간에서 정한 방향이 **바로 다음** 검증 구간에서도 맞았는가"를
봅니다. 5회 중 3회 미만이면 기각(`FAILED_WALK_FORWARD`)입니다.

**여전히 못 막는 것**: 창이 겹치므로 회차끼리 완전히 독립은 아닙니다.
전체 기간이 하나의 시장 국면이면 모든 회차가 같은 편향을 겪습니다.

---

## 4. (3) 겹치는 표본 — p-value 가 부풀려지는 문제

5일 수익률을 **매일** 계산하면, 연속한 표본은 4일치를 공유합니다.

```
1월 2일 표본: 1/2 → 1/9 의 수익률
1월 3일 표본: 1/3 → 1/10 의 수익률   ← 4일이 겹칩니다
```

표본 100건이라도 **사실상 독립인 관측은 약 20건**입니다.
이걸 보정하지 않으면 p-value 가 실제보다 훨씬 작게 나오고,
없는 우위를 있다고 말하게 됩니다.

```python
effective_sample_size(100, horizon=5)  # → 20
```

보고서에는 두 값을 모두 적어 둡니다.

```json
{
  "sample_size": 100,
  "effective_sample_size": 20,
  "p_value_naive": 0.0004,
  "p_value_overlap_adjusted": 0.12,   ← ★ 실제로 쓰는 값
  "p_value": 0.12
}
```

## 5. (4) 다중검정 보정

두 가지를 함께 계산해 보여줍니다.

| 방법 | 기준 | 성격 |
|---|---|---|
| **Bonferroni** | `p ≤ α / m` | 가장 엄격. 거의 다 떨어짐 |
| **Benjamini-Hochberg (FDR)** | `p(i) ≤ (i/m)·α` | 실무 표준. "발견한 것 중 거짓이 α 이하" |

기본값은 **BH-FDR** 입니다 (`correction="bh"`). Bonferroni 로 바꾸려면
`PatternMiner(correction="bonferroni")`.

### 실측 (합성 데이터, 6종목, 700봉)

```
후보                   153개
├ 표본 부족             50
├ 우위 없음             16
├ 검증 실패              6
├ OOS 실패              12
├ walk-forward 실패      8   ← ★ 신규 관문
├ 다중검정 탈락         43   ← ★ 신규 관문
├ 중복(REDUNDANT)        3
├ WEAK                   2
└ STRONG                 5

동시검정 100건 기준
  보정 없었다면 우연히 유의: 약 5개
  Bonferroni 통과:            1개
  BH-FDR 통과:                5개
```

**보정으로 43개가 기각되었습니다.** 그 43개는 보정이 없었다면
`STRONG` 으로 보고되었을 후보들입니다.

## 7. 검정력 — "이 표본으로 잡을 수 있나"

```python
required_sample_for_edge(0.05)   # 승률 55% → 약 780건 필요
required_sample_for_edge(0.20)   # 승률 70% → 약 40건
```

표본 30건짜리 패턴이 왜 무의미한지 이 숫자 하나로 설명됩니다.
승률 60%가 나와도 표본 30건이면 **p ≈ 0.36** 입니다. 동전던지기와 구별되지 않습니다.

## 8. 블록 부트스트랩

평균 수익률의 신뢰구간을 구할 때 일반 부트스트랩은 표본이 독립이라고 가정합니다.
수익률은 그렇지 않습니다(자기상관). 그래서 연속한 `block` 개를 통째로 뽑아
시간 구조를 보존합니다.

**신뢰구간이 0을 포함하면 → 평균 수익이 0과 구별되지 않습니다.**

---

## 9. ★ 여전히 사실인 것

이 모든 관문을 통과해도:

- **과거에 통했다는 사실이 미래를 보장하지 않습니다.**
- 합성 데이터에서 나온 결과는 실제 시장과 무관합니다
  (생성기에 의도적인 사이클이 들어 있습니다)
- 여러 종목을 합산했으므로 종목 간 상관이 높으면 실제 독립 표본은 더 적습니다

보정은 **잘못된 발견을 줄이는** 도구이지, **옳은 발견을 만드는** 도구가 아닙니다.
이 관문들의 목적은 "많이 찾기"가 아니라 **"자신 있게 버리기"** 입니다.
