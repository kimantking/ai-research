# 한국 데이터 — 공공데이터포털 + DART

> 한국 주식은 **시세**와 **공시** 두 갈래로 들어옵니다. 둘 다 무료이고 정부·감독기관 공식입니다.

---

## 1. 키 발급 (한 번만, 각 3~5분)

### ① 공공데이터포털 — 시세

1. https://www.data.go.kr 회원가입
2. `주식시세정보` 검색 → **금융위원회_주식시세정보**
3. **활용신청** (개발계정 · 자동승인)
4. 마이페이지 → 데이터활용 → Open API → 인증키

키가 **두 형태**로 나옵니다.

| | 생김새 |
|---|---|
| **일반 인증키 (Decoding)** ← 권장 | `aBcD3fG...==` (`+` `/` `=` 가 그대로) |
| 일반 인증키 (Encoding) | `aBcD3fG...%3D%3D` (`%3D` 로 바뀜) |

**어느 쪽을 넣어도 동작합니다.** 코드가 자동으로 판별합니다 (아래 4번 참고).

### ② DART — 공시

1. https://opendart.fss.or.kr 회원가입
2. **인증키 신청/관리 → 인증키 신청** (이메일 인증)
3. **40자리 16진수** 키 발급

### `.env` 에 넣기

```ini
DATA_GO_KR_KEY=발급받은_공공데이터포털_키
DART_API_KEY=발급받은_DART_40자리_키
MARKET_EXCHANGE=XKRX
```

> `.env` 는 Git 에 올라가지 않고, 로그에는 `***` 로만 남습니다.
> 화면의 Settings 에도 **키 자체가 아니라 "설정됨/안 됨" 만** 표시됩니다.

## 2. 쓰는 법

```powershell
# 한국 시세 가져오기
.\fetch-data.bat -Provider data_go_kr -Symbols 005930,000660

# 기간 지정
.\fetch-data.ps1 -Provider data_go_kr -Symbols 005930 -Start 2023-01-01 -End 2024-12-31
```

**공시**는 화면에서 봅니다: **Data 화면 → 한국 공시 조회 (DART)** 에 종목코드 입력

API 로도 됩니다:

```
GET /api/dart/filings?stock_code=005930&begin=2024-01-01&limit=30
```

## 3. ★ 공시의 두 날짜 — 이 문서에서 가장 중요한 부분

```
결산기말 / 보고 대상 기간   2024-12-31   ← 그 숫자가 '언제의 실적인가'
rcept_dt (접수일자)         2025-03-11   ← 그 숫자를 '언제 알 수 있었나'
```

앞의 날짜를 기준으로 쓰면 **12월 31일에 이미 연간 실적을 아는 것**이 됩니다.
실제로는 3월 중순에야 알 수 있었습니다. **두 달 반의 미래를 보는 셈**입니다.

이것이 퀀트에서 가장 흔하고 가장 치명적인 실수입니다.
백테스트 수익률이 환상적으로 나오고, 실전에서는 재현되지 않습니다.

**그래서 PIT Store 에 넣을 때 `published_time` 은 반드시 `rcept_dt` 입니다.**

### 재무제표 API 의 함정

`fnlttSinglAcnt.json`(단일회사 주요계정) 은 숫자를 주지만
**언제 공시됐는지는 주지 않습니다.**

그래서 이 코드는 **접수일자 없이는 PIT 레코드를 만들지 않습니다.**

```python
financials_as_pit_records(items, "005930", rcept_dt="")
# DartParseError: 접수일자(rcept_dt) 없이는 PIT 레코드를 만들 수 없습니다.
#                 결산기말을 공개일로 쓰면 몇 달의 미래를 보게 됩니다.
```

숫자를 **보는 것**은 됩니다. 다만 백테스트에 쓰려면 목록 API 에서
그 보고서의 접수일자를 먼저 확인해 짝지어야 합니다.

## 4. ★ 공공데이터포털 키 인코딩 — 최대의 함정

Decoding 키에는 `+` 가 들어 있습니다. 그것을 **URL 에 그대로 붙이면**
서버의 URL 디코더가 `+` 를 **공백으로** 바꿉니다.

```
보낸 키   : abc+def
서버가 읽음: abc def      ← 키가 달라졌습니다
결과      : SERVICE_KEY_IS_NOT_REGISTERED_ERROR
```

키는 멀쩡한데 "등록되지 않은 키" 라고 나오는 이유가 이것입니다.
검색해도 잘 안 나오는 문제라 몇 시간씩 잡아먹습니다.

**우리 코드는 자동으로 처리합니다.**

- Decoding 키(`+` `/` `=` 포함) → `%2B` `%2F` `%3D` 로 인코딩해서 전송
- Encoding 키(`%2B` 포함) → 이미 됐으므로 **그대로** 전송
  (또 인코딩하면 `%` 가 `%25` 가 되어 다시 깨집니다)

테스트 `test_decoded_key_gets_encoded_in_url`, `test_encoded_key_is_left_alone`
이 두 방향을 모두 고정합니다.

## 5. 오류가 나면 — 사유를 그대로 말해줍니다

이 API 는 JSON 을 요청해도 **오류일 때는 XML** 을 돌려줍니다.
그걸 처리하지 않으면 "JSON 파싱 실패" 라는 쓸모없는 메시지만 남습니다.

| 실제 응답 | 우리가 보여주는 말 |
|---|---|
| `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | 등록되지 않은 서비스 키입니다. **활용신청 승인 상태**와 키 복사를 확인하세요 |
| `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR` | 일일 호출 한도 초과. 내일 다시 하거나 한도 증가 신청 |
| `resultCode 03` | 해당 기간에 데이터가 없습니다 (종목코드·기간 확인) |
| `resultCode 22` | 요청 제한 횟수 초과 |

DART 도 마찬가지로 **HTTP 200 으로 오류를 돌려줍니다.** `status` 를 반드시 봅니다.

| status | 안내 |
|---|---|
| `010` | 등록되지 않은 키 → opendart.fss.or.kr 에서 확인 |
| `013` | 조회된 데이터 없음 → 기간·종목을 넓혀보세요 |
| `020` | 일일 20,000건 한도 초과 → 내일 다시 |
| `100` | 잘못된 값 → 종목코드 6자리·날짜 YYYYMMDD 확인 |
| `800` | DART 시스템 점검 중 |

## 6. 종목코드 → DART 회사코드

DART 는 자체 **8자리 `corp_code`** 를 씁니다. 우리가 아는 건 6자리 종목코드입니다.

변환표는 `corpCode.xml` 로 받는데, **실제로는 ZIP 파일**입니다.
압축을 풀면 XML 하나가 나옵니다. 이 코드가 자동으로 처리하고 캐시합니다.

```python
client.corp_code_for("005930")   # → "00126380"
client.corp_name_for("005930")   # → "삼성전자"
```

비상장사는 종목코드가 없어 변환표에서 제외됩니다.

## 7. 원주가입니다 (수정주가 아님)

금융위원회 주식시세정보는 **액면분할·병합이 반영되지 않은 원주가**입니다.

이건 오히려 **백테스트에 더 안전합니다.** 수정주가는 과거 값이 나중에 바뀌어
Point-in-Time 원칙과 충돌합니다 (`docs/MARKET_DATA.md` 6번).

다만 분할 구간에서 가격이 뚝 떨어진 것처럼 보입니다.
그래서 **하루 ±50% 이상 변동**을 "분할 의심" 으로 표시합니다.

---

## 8. 거래일 검증

한국 시세는 **XKRX 캘린더**로 검사합니다.

- 휴장일에 봉이 있으면 → 경고
- 거래일인데 데이터가 없으면 → 결손 경고
- 설날·추석은 음력이라 **2015~2035 표** 기반 (`docs/CALENDAR.md`)

실측: 2024년 데이터 245봉을 넣었을 때 **휴장일 봉 0, 결손 0** 으로
캘린더와 데이터가 일치했습니다.

## 9. 검증 상태 (정직하게)

| 항목 | 상태 |
|---|---|
| 파싱 · 필드 매핑 (`mkp`=시가 …) | ✅ 실제 응답 형식으로 검증 |
| 페이징 · 중복 날짜 병합 | ✅ 검증 |
| 키 인코딩 양방향 | ✅ 검증 |
| XML 오류 · status 코드 해석 | ✅ 검증 |
| ZIP 회사코드 변환 | ✅ 검증 |
| PIT 규칙 (rcept_dt) | ✅ 검증 |
| 품질검사 · 캘린더 연동 | ✅ 검증 |
| **실제 서버 연결** | ❌ **미검증** |

마지막 항목만 antking님 PC 에서 처음 확인됩니다.
이 개발 환경은 외부 네트워크가 차단되어 있어 두 서비스에 한 번도
접속해 본 적이 없습니다. **로컬 스텁 서버**를 만들어 전체 흐름
(시세 245봉 적재 → 품질검사 → PIT 저장 → 공시 조회 → 회사코드 변환)을
끝까지 통과시켰지만, 그건 실제 서버가 아닙니다.

**실패하면 사유를 명확히 말하도록 만들어 두었습니다.** 그 메시지를
그대로 알려주시면 고치겠습니다.
